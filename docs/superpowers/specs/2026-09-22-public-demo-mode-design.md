# Memory Fragments 公開デモモード設計

作成日: 2026-09-22

対象ブランチ: `feature/public-demo-mode`

基準コミット: `cefb6c8b11f1327d039ce126a76733abab587358`

## 1. 目的

面談担当者がアカウントを作らずに Memory Fragments の主要操作を確認できる公開デモを提供する。デモは架空データだけを使い、ログイン利用者の本物の日記・写真・認証情報・保存領域から技術的に分離する。

成功条件は次のとおり。

- 未ログインの訪問者がトップページから1操作でデモを開始できる。
- 架空の日記3件と合成写真3枚によって、完成後の利用イメージが最初から分かる。
- デモでは追加、写真添付、検索、カテゴリー・タグ絞り込み、詳細表示、削除を試せる。
- デモ中の変更はページ内のメモリだけに存在し、再読み込みすると初期データ3件へ戻る。
- デモ操作では Firebase Authentication、Firestore、Storage、Analytics、位置情報、個人用 `localStorage` の日記領域を読み書きしない。
- 通常ログイン時の既存の日記、写真、会員状態、保存・書き出し機能を壊さない。
- トップページだけでアプリの用途と実装上の工夫を短時間で把握できる。

## 2. 対象外

- デモ内容の永続保存、端末間同期、共有URLの発行
- デモでの位置情報取得、クラウド写真アップロード、課金、会員状態の変更
- 日記編集機能の新設（現行アプリに存在する追加・閲覧・検索・削除を対象とする）
- Firebaseルール、Storageルール、Cloud Functions、既存データの移行・変更
- 実在人物、実在施設、本人の写真・日記をデモ素材として使用すること

## 3. 採用方式

同一の `index.html` と表示部品を再利用し、`?demo=true` で起動するクライアント内デモモードを採用する。

検討した代替案:

1. **別の `demo.html` を作る方式**: 実装は分かりやすいが、通常画面と表示・検索・アクセシビリティ修正が二重管理になるため不採用。
2. **Firebase匿名認証とデモ用コレクションを使う方式**: 本番に近いが、公開書き込み、荒らし対策、定期削除、費用、ルール管理が必要になり、個人データ分離の説明も複雑になるため不採用。
3. **同一画面＋メモリ内ストア方式**: 既存UIを実際に操作でき、外部保存を完全に避けられる。今回の目的に最も小さく安全なので採用。

## 4. 構成

### 4.1 モード判定

ページ起動直後にURLの `demo=true` を読み、通常モードかデモモードかを確定する。モードはページ存続中に書き換えず、デモ開始・終了はURL遷移と再読み込みで行う。

- 通常: `/`
- デモ: `/?demo=true`
- デモ終了: `/` に戻る

これにより、認証状態の途中変更とデモ状態を混在させない。ログイン済みブラウザーでデモURLを開いた場合も、デモを優先し、本物の日記を読み込まない。

### 4.2 DemoMemoryStore

デモ専用の小さなストアを `js/app/demo/demo-memory-store.js` に置く。役割は次のみに限定する。

- 初期データを毎回ディープコピーして保持
- 一覧取得
- 新規追加
- ID指定の削除
- ページ内だけの画像Data URL保持
- デモの再初期化

このストアは Firebase、`MemoryRepository`、`localStorage`、Cookie、IndexedDBへ依存しない。通常の日記保存サービスからも参照しない。

### 4.3 デモ制御

ページ初期化時にデモ判定を最初に行い、デモ中はFirebaseの認証監視そのものを登録しない。Firebase SDKが通常画面用に読み込まれていても、認証状態の取得や次の通常処理を呼ばない。

- `checkPremiumStatus`
- `loadMemories` / `loadSingleMemory`
- Firestoreの追加・削除
- Storage画像読込・アップロード
- Analytics初期化・イベント送信
- オンボーディングの利用者記録
- 位置情報取得

デモ用の疑似利用者IDを `demo-session` とするが、認証済み利用者として外部サービスへ渡さない。既存の表示・検索・統計ロジックが必要とする所有者判定にだけ用いる。

### 4.4 通常処理との境界

既存関数へ無秩序に条件分岐を追加せず、外部副作用の入口で分ける。

- 読込: `startDemoMode()` がDemoMemoryStoreから `memories` を設定
- 保存: `saveMemory()` の先頭でデモ専用保存処理へ委譲
- 削除: `deleteMemory()` の先頭でデモストアから削除
- 写真表示: `renderPrivatePhoto()` は `demoImageUrl` の場合のみ静的URL/Data URLを直接表示し、Storageを呼ばない
- 詳細表示: デモ所有者を許可する共通の所有者判定関数を使う
- 通常モード: 現在のFirebase経路を維持

デモ専用コードが通常モードで呼ばれた場合は何も変更せず失敗させる。通常の保存サービスがデモIDを受け取った場合も外部書き込みしないよう防御する。

## 5. 架空データと写真

初期データは3件とする。

1. **海辺で見た夕焼け** — 旅行、タグ: `海` `夕焼け` `週末`
2. **静かなカフェで読書** — 趣味、タグ: `読書` `カフェ` `休日`
3. **小さな目標を達成した日** — 日常、タグ: `目標` `振り返り` `成長`

本文、日時、タグ、カテゴリーはすべて架空とし、実在人物・企業・住所・連絡先を含めない。

写真は画像生成で作る人物なしの合成画像3枚（夕方の海辺、静かなカフェの本と飲み物、付箋とノートの机）を `assets/demo/` に保存する。ファイル名、画面上の説明、代替テキストで「デモ用合成画像」であることを明示し、実在の出来事と誤認させない。外部画像URLは使わない。

デモ利用者が選んだ写真はブラウザーの `FileReader` でData URL化し、そのページのメモリ内だけに保持する。サイズ・形式検証は現行フォームと同等にし、ページを離れると消える。

## 6. 画面設計

### 6.1 トップページ

タイトル直下に短い紹介カードを追加する。

- 何ができるか: 「日記と写真を記録し、検索・分類・振り返りができる個人向けWebアプリ」
- 工夫: 「本人認証付き写真表示」「クラウド保存と端末内フォールバック」「検索・統計」「個人データと公開デモの分離」
- 主ボタン: `デモを試す（ログイン不要）`
- 補足: `操作内容は保存されず、架空データだけを使用します`

ログインフォームは残し、個人利用とデモ体験の選択肢を明確に分ける。スマートフォンでは紹介、デモボタン、ログインの順に縦並びにする。

### 6.2 デモ画面

画面上部へ常時表示するバナーを設ける。

- `デモモード` ラベル
- `架空データのみ。変更は再読み込みでリセットされます`
- `デモを終了` ボタン

フォーム、検索、タグ、統計、日記カードは通常UIを再利用する。位置情報は非表示または無効化し、理由を短く表示する。共有、書き出し、課金、クラウド同期を示す操作は表示しない。保存結果は「デモに追加しました。再読み込みすると消えます」と明示する。

## 7. 操作とデータフロー

### デモ開始

1. 訪問者が `デモを試す` を押す。
2. `/?demo=true` へ遷移してページを初期化する。
3. Firebase認証監視を登録せず、デモ初期データを読み込む。
4. 架空データ3件を一覧表示する。

### デモ保存

1. 通常と同じ必須入力検証を行う。
2. 選択写真があれば形式・サイズを確認してData URLにする。
3. DemoMemoryStoreへ追加する。
4. フォームをクリアし、一覧・統計・タグを再描画する。
5. Firebase・端末保存は呼ばない。

### 検索・詳細

既存の表示、文字検索、日付、カテゴリー、タグ、統計を同じ `memories` 配列に対して実行する。URLに本物の日記IDを渡しても、デモストア内に存在しなければ「見つかりません」とし、Firestoreへフォールバックしない。

### 削除・再読み込み

確認後、DemoMemoryStoreだけから削除する。再読み込みするとストアが初期データを複製し直すため、3件へ戻る。

## 8. エラー処理と安全性

- デモ画像の読込失敗は、そのカードだけ説明付きプレースホルダーにする。
- 写真の形式・サイズが不適切ならフォーム内容を保持して理由を表示する。
- デモ保存中の例外でも通常のクラウド保存へフォールバックしない。
- デモ中のFirestore/Storage/Analytics/Geolocation呼出しはテスト用の失敗する境界で検知する。
- デモ用文字列も通常の日記と同様にHTMLエスケープする。
- `demo=true` は権限を付与する値ではなく、外部アクセスを減らす表示モードとしてのみ扱う。
- 本物の認証状態・UID・メールアドレスをデモUIへ表示しない。

## 9. アクセシビリティとモバイル

- デモ開始・終了はbutton/linkとしてキーボード操作可能にする。
- バナーへ状態を表す見出しと説明を付ける。
- 合成写真には内容と合成画像であることを伝える日本語の代替テキストを付ける。
- 360px幅でボタンやカードが横にはみ出さず、タップ対象を十分な大きさにする。
- 色だけに依存せず「デモモード」の文字を表示する。
- 動きの軽減設定がある場合も主要操作を阻害しない。

## 10. テスト

テスト駆動で次を先に失敗させてから実装する。

### データ分離

- 未ログインとログイン済みの両方で `?demo=true` を起動してもFirestore/Storage/Analytics/位置情報を呼ばない。
- デモ追加・削除・写真添付でFirebase書込と個人用localStorage変更が0件。
- 本物の日記IDを指定してもFirestoreを読まない。
- 通常モードの既存保存・写真・課金保護テストが引き続き通る。

### 操作

- 初期表示は日記3件・合成画像3枚。
- 追加で4件になり、検索・タグ・カテゴリーで絞り込める。
- 削除で対象だけが消える。
- 新しいJSDOMページを作ると3件へ戻る。
- 写真Data URLがページ内で表示される。
- デモ終了は通常URLへ戻る。

### 公開物と画面

- ビルドにデモ用コードと画像3枚が含まれる。
- デモ画像に実データや外部URLがない。
- トップの用途・工夫・ログイン不要表示がある。
- 360px相当とデスクトップ幅でブラウザー確認する。
- 本番反映後、配信ハッシュ、画像HTTP 200、購入導線なし、コンソールエラーなしを確認する。

## 11. リリース

既存の積み上げPR構成を維持し、この変更は `fix/portfolio-no-checkout` を基底とする新しいPRにする。`main` へは自動マージしない。

反映対象はVercelの公開Web資産だけとする。Firebaseルール、Storage、Functionsはデプロイしない。公開前に現在の本番HTMLが基準コミットと一致することを確認し、競合する外部変更があれば停止する。

本番反映後も実日記の追加・削除は行わず、デモ操作だけで確認する。問題時は直前のVercelデプロイへ戻せるようデプロイIDを記録する。
