# GitHub Portfolio Polish Design

## 目的

Memory Fragments を、技術面談の担当者が短時間で「何を作ったか」「どの問題をどう直したか」「どこまで検証したか」を確認できる GitHub 実績へ整える。

対象読者は、エンジニア採用担当者、開発責任者、案件発注者とする。公開デモはログイン不要で試せる状態を維持し、本番利用者のデータや個人情報は掲載しない。

## 採用する方針

### 1. 旧版は削除せず隔離する

現在のルートには、旧画面、手動試験ページ、障害対応メモ、過去の決済実装、未使用の JavaScript が混在している。これらは履歴として残しつつ、`archive/` 配下へ用途別に移動する。

- `archive/legacy-app/` — 旧画面、試験ページ、現在使っていない JavaScript/CSS
- `archive/notes/` — 過去の設定手順、障害対応メモ、検討資料
- `archive/payment-reference/` — 現在は公開していない Stripe / Cloud Functions 実装
- `archive/config/` — 現在の配信・テストで使っていない設定ファイル
- `archive/external-references/` — 本体と無関係な過去の Git リンク

`archive/README.md` に、保存理由、本番未使用であること、各分類の意味を記載する。今回はファイルを削除しない。

## 2. README を実際の動作に合わせる

README の冒頭だけで以下が分かる構成にする。

1. アプリの目的
2. 本番URLとログイン不要のデモURL
3. PC版・スマートフォン版の画面例
4. 実装済み機能
5. 自動テストで検証済みの範囲
6. 現在の制約・未対応事項
7. 技術構成とデータの流れ
8. 問題を発見し、修正し、検証した改善事例
9. ローカルでのテスト・ビルド手順

決済コードは実装記録として残すが、現在は新規課金を受け付けていないことを明記する。過去の「50件を超えると月額制」「Stripe Checkout で決済する」という現行サービスに見える記述は削除する。

## 3. 画面例は架空データだけを使う

本番公開中の次の2画面を取得し、`docs/images/` に保存する。

- `public-landing-desktop.png` — PC幅のトップページ
- `public-demo-mobile.png` — スマートフォン幅の公開デモ

公開デモには架空の日記・生成画像だけを使用し、個人アカウントへログインしない。画像は GitHub 上で読める解像度を保ち、不要に巨大なファイルにはしない。

## 4. 改善内容を技術判断として説明する

README では、単なる機能一覧ではなく、次の改善を「問題 → 原因 → 対応 → 検証」の順で簡潔に説明する。

- 写真URLの共有状態から、本人認証付き表示へ変更
- クライアントから変更できた有料会員状態を、サーバー側ルールで保護
- IndexedDB とクラウド保存の結果を区別し、保存失敗を明示
- JSON / CSV / TXT / HTML 書き出しの日付処理と安全性を統一
- 個人用データと公開デモ用メモリストアを分離
- 公開ビルドを許可リスト方式にし、旧版・ルール・ログを配信対象外にした

## 5. GitHub Actions で検証結果を見せる

`.github/workflows/ci.yml` を追加し、プルリクエストと主要ブランチへの push で次を実行する。

1. Node.js 22 と Java 21 をセットアップ
2. `npm ci`
3. `npm test`
4. `npm run build`

Firebase Emulator を含むテストを `npm ci` 後だけで再現できるよう、`firebase-tools` を固定バージョンの開発依存へ追加する。

## 6. 自動テストでポートフォリオの整合性を守る

既存の機能・セキュリティテストは維持し、次の回帰テストを追加する。

- 既知の旧版ファイルがルートから `archive/` に移動済み
- アーカイブの説明と代表ファイルが存在
- README が公開URL、デモURL、実装済み、検証済み、制約を明記
- README が現在課金を提供していると誤認させない
- README から参照する画面画像が存在し、PNGとして有効
- CI がテストとビルドを実行
- 公開ビルドに `archive/`、`docs/`、`.github/` が含まれない

## 本番への影響

`index.html`、現在利用中の JavaScript、Firebase ルール、公開デモ用データの挙動は変更しない。ビルドは既存の許可リスト方式を維持するため、文書整理やアーカイブは本番配信へ含まれない。

## 完了条件

- 旧版・試験用ファイルが削除されず、用途別に隔離されている
- README の記述が現在の本番動作と一致している
- 架空データだけのPC版・スマートフォン版画像が表示される
- GitHub Actions の構成があり、ローカルで全テストと本番ビルドが成功する
- PR #6 上で変更内容と検証結果を確認できる
